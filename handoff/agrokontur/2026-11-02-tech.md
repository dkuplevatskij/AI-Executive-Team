## Задачи (по убыванию важности)

### A-1. Приложение стартует со слабыми секретами по умолчанию — высоко
- **Что не так:** в `docker-compose.yml` значения по умолчанию: пароли PostgreSQL и RabbitMQ `agrokontur`,
  `JWT_SECRET_KEY=change-me-in-production`; приложение только пишет предупреждение и запускается
  (`backend/app/main.py:21`).
- **Почему важно:** если на проде значения не переопределены — токены входа можно подделать.
- **Что сделать:** в production-режиме отказываться стартовать при значении секрета по умолчанию или
  слишком коротком; убрать небезопасные значения по умолчанию из compose для прода.
- **Готово, когда:** с `change-me-in-production` в production приложение не стартует; тест.

### A-2. Резервное копирование не описано — высоко
- **Что не так:** в репозитории не описано, как и куда копируются БД и тома документов
  (`agrokontur_db_data`, `agrokontur_documents`).
- **Что сделать:** описать текущее состояние со слов собственника; при отсутствии — скрипт копии во
  внешнее хранилище и проверка восстановления.
- **Готово, когда:** есть ежедневная копия вне сервера и записанная процедура восстановления.

### A-3. Проверить, выкачен ли PR #215 — средне
- **Что не так:** последняя успешная выкладка — 21.10.2026 (`ae9da83`); после неё в main слит PR #215
  (изменение CI «deploy exactly the tested commit»). Выкачен ли он — неизвестно.
- **Что сделать:** сверить версию на проде с main; при расхождении — сообщить собственнику (выкладка вручную).

### A-4. Устаревший раздел о CI в `CLAUDE.md` — низко
- **Что не так:** `CLAUDE.md` пишет, что CI красный из-за исчерпанного лимита Actions, но запуски
  21–22.10.2026 успешные.
- **Что сделать:** уточнить у собственника остаток минут и обновить раздел.

### A-5. Неподдерживаемая библиотека паролей — низко

- **Что сделать:** оценить переход (например, на прямое использование `bcrypt`/`argon2-cffi`) без
  изменения поведения входа; план — собственнику.
