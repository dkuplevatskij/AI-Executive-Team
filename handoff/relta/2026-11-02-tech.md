## Задачи (по убыванию важности)

### R-1. `npm run build` может стереть данные — критично
- **Что не так:** скрипт `build` в `package.json` (строка 7) содержит `prisma db push --accept-data-loss`.
  `CLAUDE.md` предупреждает об этом, но скрипт остался.
- **Почему важно:** запуск `npm run build` с серверным `.env` молча приводит прод-базу к схеме и удаляет «лишнее».
- **Что сделать:** убрать `prisma db push --accept-data-loss` из `build`; если нужен — отдельный явный скрипт
  с понятным именем, только для локальной базы.
- **Готово, когда:** `npm run build` не трогает базу; `CLAUDE.md` обновлён.

### R-2. Живая ошибка БД в контейнере — высоко
- **Что не так:** issue #247 «[error-watch] infra-app-1: prisma:error» открыт с 26.10.2026.
- **Что сделать:** разобрать по логам, какой запрос падает, исправить причину.
- **Готово, когда:** ошибка не повторяется, issue закрыт со ссылкой на PR.

### R-3. На pull request нет проверок — высоко
- **Что не так:** `tsc`, `typecheck:wa` и `vitest` запускаются только на push в main внутри `deploy.yml`
  (около строк 42, 60); на PR — ничего.
- **Почему важно:** ошибка обнаруживается уже в момент выкладки.
- **Что сделать:** отдельный workflow на `pull_request` с теми же проверками и `npx next build`.
  Учесть лимит минут Actions (уточнить у собственника).
- **Готово, когда:** PR с ошибкой типов получает красную проверку.

### R-4. MRR в админке считается по таблице, в которую никто не пишет — высоко
- **Что не так:** `admin.revenueChart` считает MRR по `BillingHistoryItem`, но в коде нет ни одной записи в
  эту таблицу (`billingHistoryItem.create` не найден). Оплаты включаются вручную (`admin.changePlan`).
- **Почему важно:** админка показывает выручку, которой нет (или ноль, когда оплата была).
- **Что сделать:** при ручном включении платного тарифа писать запись об оплате (сумма, период, способ —
  «по счёту»), либо подписать график «нет данных» до подключения оплаты.
- **Готово, когда:** график выручки совпадает с фактом, известным собственнику.

### R-5. Whisper не учитывается в себестоимости — средне
- **Что не так:** `src/lib/whisper.ts` не вызывает `recordLlmUsage`; отчёт `admin.llmCostReport` неполный.
- **Что сделать:** писать расход транскрипции (секунды аудио, стоимость) в `LlmUsage`.

### R-6. Уязвимая зависимость `xlsx` — средне
- **Что не так:** `xlsx@^0.18.5` — версия с известными уязвимостями, исправлений в npm нет.
- **Что сделать:** перейти на поддерживаемую сборку (официальный CDN SheetJS) или другую библиотеку;
  проверить места использования.

### R-7. `CLAUDE.md` расходится с кодом — низко
- **Что не так:** «Next.js 14» при `^15.5` в `package.json`; «vercel.json cron» при `infra/cron`.
- **Что сделать:** привести к факту.

### R-8. Мусор эпохи Manus/Vercel/AWS в корне — низко
- **Что не так:** `devops-audit.zip`, `diagnostic-files.zip`, `DIAGNOSTIC_*.md`, `DEVOPS_*.md`, `MANUS_TASK.md`,
  `AUDIT_REPORT.md`, `terraform/`, `scripts/deploy-to-aws.sh`, `Dockerfile.backend/.frontend`, `vercel.json`,
  `capture_console.js`; поля Stripe в `Subscription`; неиспользуемая `@aws-sdk/s3-request-presigner`.
- **Что сделать:** список к удалению — **на согласование собственнику**, потом один PR.
