## Задачи (по убыванию важности)

### AH-1. Роль `admin` получает доступ к суперадминке — критично
- **Что не так:** `superAdminProcedure` пускает не только `superAdmin`, но и `admin` (`server/routers.ts:48–52`).
- **Почему важно:** если роль `admin` выдаётся сотрудникам агентств, они видят и меняют данные всей
  платформы (тарифы, подписки, все агентства).
- **Что сделать:** выяснить по коду, кому выдаётся `admin` (регистрация, приглашения, `create-admin.ts`).
  `superAdminProcedure` — только `superAdmin`. Если `admin` нужен для админки агентства — отдельная
  процедура с проверкой принадлежности к агентству.
- **Готово, когда:** пользователь с ролью `admin` получает отказ на всех процедурах суперадмина; тест на это.
- **Проверка:** новый тест в `server/` + `pnpm check`.

### AH-2. Документация API открыта публично — высоко
- **Что не так:** Swagger на `/api-docs` доступен без входа (`server/_core/index.ts:257–258`).
- **Почему важно:** раскрывает всю поверхность API, упрощает атаки.
- **Что сделать:** отключить в production или закрыть входом суперадмина.
- **Готово, когда:** в production `/api-docs` отдаёт 404/401; в разработке работает.

### AH-3. Выкладка в прод без тестов и проверки типов — высоко
- **Что не так:** `.github/workflows/deploy.yml` выкатывает каждый push в main без тестов и `tsc`.
  По описанию PR #40, 47 тестов уже падают на main, потому что требуют сеть, БД или ключ LLM.
- **Почему важно:** любая ошибка сразу у пользователей.
- **Что сделать:** разделить тесты на «быстрые» (без сети) и «интеграционные»; в deploy — шаги
  `pnpm check` и быстрые тесты до выкладки, выкладка только при зелёных.
- **Готово, когда:** деплой не запускается при красном `tsc` или быстрых тестах; быстрые тесты зелёные.

### AH-4. Схема БД меняется без миграций — высоко
- **Что не так:** миграции в прод не накатываются, таблицы создаются кодом «при первом обращении»
  (`server/billing.ts`, шапка), есть ручной `scripts/register-migration.mjs` (0014–0015).
- **Почему важно:** схема на проде расходится с кодом; откат и восстановление непредсказуемы.
- **Что сделать:** снять фактическую схему прода (собственник даёт выгрузку схемы без данных), сделать
  базовую миграцию Drizzle, накатывать миграции при деплое; убрать создание таблиц из кода.
- **Готово, когда:** чистая БД поднимается только миграциями; деплой применяет миграции.

### AH-5. Расход на ИИ не учитывается — средне
- **Что не так:** `server/_core/aiBudget.ts` считает вызовы в памяти, обнуляется при перезапуске;
  токены и стоимость не пишутся.
- **Почему важно:** счёт OpenAI/Vercel не контролируется; финансы портфеля без себестоимости.
- **Что сделать:** таблица использования (вид вызова, модель, токены/секунды аудио, стоимость, агентство,
  дата) по образцу `UsageEvent` в agent-trainer; лимит читать из неё.
- **Готово, когда:** каждый вызов LLM/STT/TTS оставляет запись; лимит переживает перезапуск.

### AH-6. Ошибка почты на проде — средне
- **Что не так:** issue #27 — «Email service not configured (SMTP_HOST or RESEND_API_KEY)».
- **Что сделать:** при старте в production явно проверять настройки почты и писать понятную ошибку;
  сам ключ задаёт собственник (см. ниже).
- **Готово, когда:** после настройки собственником письма уходят, issue #27 закрыт.

### AH-7. Аналитика отдаёт демо-данные — низко
- **Что не так:** `server/analytics-router.ts` возвращает захардкоженные значения (`deliveryTime: 1200`).
- **Что сделать:** считать из реальных таблиц или скрыть раздел до реализации.

### AH-8. Наследие Manus и мусор в корне — низко

- **Что сделать:** составить список к удалению и **спросить собственника**, потом удалить одним PR.
