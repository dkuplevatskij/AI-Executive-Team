# /product-review — разбор продукта

Продукт: **$ARGUMENTS**.

## Шаги

1. Найди `$ARGUMENTS` в `portfolio/registry.yaml`. Нет такого id — покажи собственнику список id
   из реестра и остановись. Не угадывай.
2. **Head PM** (`head-pm`): задание — «Продукт `$ARGUMENTS`. Обнови карточку по свежим данным GitHub
   (коммиты, PR, issues, запуски выкладки) и аудиту; верни отчёт по `templates/director-report.md`
   и список изменённых полей карточки». Head PM — единственный, кто правит карточку.
3. Параллельно, если продукт в статусе Beta/Production или собственник просит глубже:
   - **CTO**: технические проблемы и риски продукта сейчас, оценка трудоёмкости главных доработок;
   - **CRO**: монетизация — что работает, что мешает начать или увеличить оплату;
   - **CMO** (по запросу): позиционирование и соответствие лендинга реальным функциям.
4. **Сведи** отчёты: где директора расходятся — покажи обе позиции. Финансовые цифры — только из
   карточки и `finance/`, не из головы директоров.
5. **Отчёт** по `templates/report.md` → `reports/reviews/ГГГГ-ММ-ДД-$ARGUMENTS.md`. В разделе
   «Рекомендации» — что делать с продуктом в ближайший месяц и какие ресурсы нужны (время, деньги,
   решения собственника).
6. **Доклад собственнику** — до 8 строк.

## Правила
- Код продукта не меняется; задачи в репозитории продукта — только если собственник попросил.
- Метки достоверности обязательны. «Нет подтверждённых данных» — нормальный ответ.
