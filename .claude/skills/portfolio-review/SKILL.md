# /portfolio-review — обзор портфеля

Режим: $ARGUMENTS (пусто = полный обзор; «кратко» — только шаги 1–2 и резюме).

## Шаги

1. **Сводка по файлам — без ИИ.** Выполни `python3 tools/portfolio_snapshot.py`. Это основа таблицы:
   статусы, свежесть карточек, заполненность, денежные поля. Карточки «УСТАРЕЛА» — отметь в отчёте;
   продукт без карточки — проблема, сообщи собственнику.
2. **Свежая активность из GitHub** — для каждого продукта из `portfolio/registry.yaml` сам
   (инструменты `mcp__github__*`, только чтение): дата последнего коммита в основной ветке, число
   открытых PR и issues, статус последнего запуска выкладки (если есть Actions). Это факты с датой.
3. **Деньги.** Если в `finance/` есть данные за последний месяц — попроси CFO короткую сводку по
   продуктам (выручка, расходы, MRR — только подтверждённое). Нет данных — так и пиши: «финансовых
   данных нет», без оценок.
4. **Риски и перспективы.** Для полного обзора — параллельно:
   - CTO: топ-3 технических риска портфеля по свежим данным (кратко, со ссылками);
   - CPO: позиция каждого продукта (продолжать / проверить гипотезу / пауза) с обоснованием.
   Директорам передай таблицу из шагов 1–2, чтобы они не собирали её заново.
5. **Противоречия.** Сравни выводы директоров между собой и с карточками; расхождения — в отдельный
   раздел, с источниками обеих сторон (при необходимости — CDO).
6. **Отчёт** по `templates/report.md` → `reports/reviews/ГГГГ-ММ-ДД-portfolio.md`. Обязательно:
   сравнительная таблица всех продуктов; приоритеты портфеля (не только по прибыли — с учётом
   долгосрочного потенциала); решения, требующие собственника.
7. **Доклад собственнику** в чате — до 10 строк: что изменилось, топ-3 проблемы, что решить.

## Правила
- Метки достоверности обязательны (`.claude/rules/data-integrity.md`).
- Отсутствующие данные не заполняются оценками; в резюме — честно, чего не хватает для полного обзора.
- Ничего не меняй в репозиториях продуктов. Карточки обновляет Head PM, а не этот сценарий.
