# /new-product-onboarding — подключение нового продукта

Аргументы: **$ARGUMENTS** (репозиторий `owner/repo` и, если указано, название).

Добавление продукта в портфель — решение собственника. Сценарий запускается только по его прямой
просьбе; если неясно, хочет ли он добавить продукт или только посмотреть, — спроси.

## Шаги

1. **Доступ.** Прочитай README репозитория через `mcp__github__get_file_contents`. Ошибка доступа →
   объясни собственнику простыми словами: репозиторий нужно добавить в сессию (в облаке — выбрать его
   при запуске сессии) или выдать приложению Claude доступ к нему на GitHub. Дальше не идти.
2. **Идентификатор.** Придумай `id` латиницей, коротко (`relta`, `agent-hunter`). Проверь, что такого
   id и такого репозитория ещё нет в `portfolio/registry.yaml`. Есть — остановись и сообщи.
3. **Аудит.** CTO по заданию `templates/repo-audit-brief.md` (для продукта с пользователями — ещё
   CISO по разделу 9). Отчёт сохрани: `audit/ГГГГ-ММ-ДД/<id>.md`.
4. **Реестр.** Добавь запись в `portfolio/registry.yaml` в формате остальных записей: статус — по
   разделу 2 аудита, `launched` — со слов собственника (не знаешь — спроси), `pm: head-pm`,
   `added` — сегодня, `source` — ссылка на аудит. Обнови `updated:` реестра.
5. **Карточка.** Head PM (`head-pm`): «Продукт `<id>`. Создай карточку `portfolio/<id>/card.md` по
   `templates/product-card.md` из аудита и свежих данных GitHub; поля без данных — «Нет подтверждённых
   данных»; цели на квартал — «Не заполнено — ждёт решения собственника»».
6. **Проверка качества.** CDO: проверить карточку (источники, нет предположений под видом фактов,
   23 поля). Затем `python3 tools/portfolio_snapshot.py --check` — должен завершиться без проблем.
7. **Журнал.** Дописать в `company/decisions/log.md`: «D-NNN · дата · Продукт `<id>` добавлен в
   портфель · Принял: собственник · Источник: просьба в сессии».
8. **Отчётность.** Ничего настраивать не нужно: `/portfolio-review`, `/daily-briefing` и финансы берут
   продукты из реестра. Если у продукта есть свои данные о деньгах — CFO заведёт строку в `finance/`.
9. **Доклад собственнику** — что подключено, главные выводы аудита, вопросы к нему (раздел 12 аудита).

Всё — в отдельной ветке и PR управляющего репозитория. Репозиторий продукта не меняется.
