## Контекст для менеджера продукта

**Как ведётся разработка.** Собственник ведёт разработку сам в сессии RELTER (в репозитории `dkuplevatskij/relter`). Управляющий центр туда не пишет: ни кода, ни веток, ни PR, ни issues, ни комментариев; к сессии не обращается. Технические задачи — только заданием в `handoff/relter/` (D-010), пересылает собственник. Задание пилота: `handoff/relter/2026-11-06-pilot.md` (RP-1…RP-7; по аудиту RP-1, RP-2, RP-4 сделаны, RP-3 частично, RP-5 без проверки на живых моделях, RP-6 не проверен вживую, RP-7 конфигурация есть, сервера нет).

**Правила репозитория (`relter/CLAUDE.md`, кратко)**
- ТЗ пилота `TZ-relter-pilot.md` — единственное ТЗ. Работа по этапам строго по порядку; этап начинается с плана, код — после «ок» собственника.
- Ветка на этап `stage-N-...`; в `main` напрямую не пушить; **PR сливает и выкладывает на сервер только собственник**. Перед слиянием этапа — проверка тестами (qa) и обзор безопасности.
- Проверки перед push: типы, тесты, `npx next build` (не `npm run build`, если в него попадёт `prisma db push`). После изменения `schema.prisma` — новая миграция в `prisma/migrations`; прод накатывает только миграции.
- Секреты только в `.env` на сервере, не в чате и не в коде; `.env.example` с пустыми значениями. Ничего не удалять сверх задачи без вопроса.
- Жёсткие правила продукта: слово «Мэтч»; карточки открытые; код CRM 10 цифр; имён и телефонов клиентов в базе нет; очередь, а не лента; функции «вне пилота» (раздел 13 ТЗ) не добавлять; тексты по-русски.
- Claude-модель с серверами за рубежом работает с реальными текстами только после подтверждения собственником законного основания передачи; до этого выключена флагом.

**Инфраструктура.** Свой сервер в РФ (не выбран; не общий Timeweb с пятью сайтами других продуктов), свой Caddy. С Timeweb связь с Telegram заблокирована, поэтому бот идёт через узел в Амстердаме (общий Caddy); блок Caddy в Амстердаме не применён и ждёт согласия собственника. Вмешательство в инфраструктуру — только собственник (уровень 3).

**Решения собственника.** D-022 (06.11.2026): девятый продукт портфеля, не заказ студии; пилот в агентстве, затем рынок; данные из выгрузки baza.ayax.ru; модели Yandex AI Studio и Claude. D-023: для рынка — коммерция в смешанной модели, жильё позже; до публичной версии проверка спроса в Краснодаре. D-024: сначала пилот в департаменте коммерческой недвижимости, интервью отложены (к проверке спроса вернуться после пилота; материалы `reports/plans/2026-11-06-relter-demand-test.md`). D-025: несколько агентств с первого дня; проверка подписи Telegram при входе, затем сессия 12 ч.
