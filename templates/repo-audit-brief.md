# Задание на аудит репозитория продукта

Единое задание для CTO (или CTO + CISO), чтобы аудиты разных продуктов были сравнимы.
Этим заданием сделан аудит 2026-11-02. Используется в `/new-product-onboarding` и при повторном аудите.

---

Только чтение: ничего не правь, не коммить, не устанавливай, не создавай PR, issues и комментарии.
Можно: читать файлы, `git log / ls-files / branch -a / show`, grep, инструменты GitHub на чтение.
Не выводи значения секретов: нашёл ключ или `.env` в git — укажи только путь и вид секрета.

Каждое утверждение — факт с источником (файл, коммит, номер PR) или явно помеченный «вывод».
Неизвестное — «нет подтверждённых данных». Пользователей, выручку и метрики не выдумывать.
`CLAUDE.md` репозитория учитывай, но проверяй по коду: он бывает устаревшим.

Разделы отчёта (по-русски, строго эти):
1. Название и назначение; боевой домен, если есть.
2. Статус: Development / Beta / Production — с доказательством (деплой, домен, прод-конфиги).
3. Целевая аудитория и проблема пользователя.
4. Монетизация: что реально в коде (провайдер, тарифы, файл с ценами), что только в планах.
5. Стек и архитектура; где хостится; схема выкладки.
6. Источники бизнес-данных: таблицы пользователей, подписок, платежей, расхода на ИИ (файлы схемы);
   админ-отчёты и скрипты метрик.
7. Состояние разработки: коммиты (всего, первый, последний, за 30 дней), открытые PR и issues,
   ветки (сколько, сколько заброшено), релизы.
8. Качество: тесты (сколько файлов), CI (файл), линт и типы; идут ли тесты перед выкладкой.
9. Безопасность: `.env` и секреты в git, слабые значения по умолчанию, открытые порты и админки,
   заметно устаревшие зависимости.
10. Технический долг — конкретные находки с путями.
11. Риски: технические (топ-3) и бизнес (топ-3), помечены «вывод», с обоснованием.
12. Вопросы к собственнику — то, что нельзя выяснить из кода.

Объём — до ~900 слов.
