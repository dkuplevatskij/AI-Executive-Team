Данные на: 2026-11-02. Составил: CDO. Следующий пересмотр: при первой выгрузке собственника или не позднее 2026-12-02.
Основание: `audit/2026-11-02/00-portfolio-audit.md` (раздел 3), аудиты по продуктам (раздел 6 каждого), карточки `portfolio/*/card.md`, выборочная сверка с кодом в локальных клонах `/home/user/<репозиторий>`.

## Как читать

**Доступно системе.** На 02.11.2026 ни одна база продукта системе недоступна и не должна быть (`.claude/rules/security-policy.md`). Прямой доступ у центра есть только к коду и истории GitHub (чтение). Все цифры из баз и кабинетов приходят выгрузкой собственника в `finance/inputs/` (папки пока нет), только агрегаты, без персональных данных.

**Доверие** (оценка CDO по тому, как данные попадают в источник; сами значения не проверялись):

| Уровень | Смысл |
|---|---|
| Высокая | пишется автоматически, расхождение с реальностью не ожидается |
| Средняя | пишется кодом или вручную; возможны пропуски, ручные правки или несверенные тарифы |
| Низкая | данные тестовые, плановые или устаревшие |
| Не использовать | источник пуст или отдаёт демо-значения: из него получится ложный ноль или выдумка |
| Нет источника | данных не хранится нигде в продукте |

**Обновление.** «Живой» = база меняется постоянно, но истории срезов (снимков по месяцам) нет: прошлые месяцы восстанавливаются только по счетам и выпискам собственника.

| Источник | Что в нём | Продукты | Доверие |
|---|---|---|---|
| Банковская выписка, выставленные счета | поступления за RELTA и Agent Hunter (оплата по счёту) | RELTA, Agent Hunter | Высокая, главный источник поступлений |

## 4. Чего нет нигде

1. **Фактических платежей в базе нет ни у одного продукта.** Выручка и поступления существуют только в выписке, счетах и кабинете CloudPayments. MRR из баз продуктов не считается (у RELTA таблица платежей пуста).
2. **Реестра выставленных счетов нет.** Оплата RELTA и Agent Hunter ручная: кто, сколько и за какой период, нигде не записано.
3. **История подписок и отток.** Таблицы хранят текущее состояние (статус, `paidUntil`); журнала смен статусов в аудитах не найдено. Churn и LTV считать не из чего. Для Agent Hunter нет и дат смены статусов кандидатов (`candidateStageHistory` в схеме есть, использование в метриках не подтверждено).
4. **Расход на ИИ не учитывается у Agent Hunter, OnFive, NAlog**; у RELTA не учитывается Whisper; у Агроконтура не учитывается Yandex Vision и Checko; у Brokers City Gemini. Единственный полный учёт, AgentScore, не запущен.
5. **Расходы на привлечение.** Нет нигде (ни рекламных бюджетов, ни источника лида: у Agent Hunter нет UTM у кандидата). CAC не считается.
6. **Доля общего сервера по продуктам.** Один сервер и один Caddy на пять доменов, один счёт: распределения затрат нет. Пятый домен, rexeed.ru, вне портфеля (D-001), но делит сервер.
7. **Единый идентификатор человека между продуктами.** Нет; пересечение аудитории RELTA, Agent Hunter и AgentScore измерить нельзя.
8. **Срезы по месяцам.** Ни один источник не хранит ежемесячные снимки пользователей и MRR; история только по счетам собственника.
9. **Фактическое число пользователей** нет подтверждённых данных ни по одному продукту (аудит, раздел 2).
10. **Бэкапы.** Где лежат и проверялись ли, нет данных (OnFive: на том же сервере; Агроконтур: не описаны).

## 5. Что начать собирать (рекомендации, решает собственник и CTO)

1. Собственнику: ежемесячная выгрузка по шаблону в `finance/inputs/YYYY-MM/`: платящие клиенты, суммы счетов и поступлений, счета Timeweb/Anthropic/OpenAI/Vercel, число пользователей из `admin.stats` (RELTA), `admin.getStats` (Agent Hunter), `/api/admin/summary` (OnFive), Umami (NAlog). Без персональных данных.
2. CTO: писать платежи и счета в БД (RELTA `BillingHistoryItem` при ручном включении тарифа; Agent Hunter, OnFive аналогично), иначе MRR остаётся ложным нулём.
3. CTO: учёт расхода на ИИ по образцу `LlmUsage` / `UsageEvent` в Agent Hunter, OnFive, NAlog и учёт Whisper в RELTA; один формат (модель, токены, стоимость, дата, продукт).
4. CDO и CFO: определить в `company/data/metrics.md` термины «запущен», «пользователь», «платящий», «MRR» одинаково для всех продуктов (сейчас Агроконтур «запущен» при тестовых данных).
