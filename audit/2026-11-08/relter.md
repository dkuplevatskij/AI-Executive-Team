**9. Безопасность.**
- **initData** [ФАКТ: `initData.ts:46-49, 95-112`]:
  - HMAC по алгоритму Telegram;
  - `timingSafeEqual` после проверки формата hash (64 hex);
  - срок `auth_date` не больше 3600 с (`env.ts` не даёт поставить больше), не из будущего (допуск 5 мин);
  - повтор ключей и размер больше 4 КБ отклоняются.
- **Серверная сессия** [ФАКТ: `session.ts`, `token.ts`]:
  - 12 ч абсолютно;
  - токен 32 байта CSPRNG, в БД только SHA-256;
  - роль и `agencyId` читаются из БД на каждом запросе;
  - деактивация брокера удаляет его сессии;
  - [по ревью] токен хранится в памяти страницы, не в cookie.
- **Белый список** [ФАКТ: `login.ts`]. Вход ищет запись по `tgId`. Записи без `tgId` можно привязать по @username, если совпадение ровно одно. Это соответствует RP-2.
  - Остаточный риск (Ж-1 в `security-review.md`): непривязанный @username ищется по всем агентствам (`login.ts:35-41`). Админ агентства Б может заранее вписать @username брокера агентства А, и первый вход привяжет брокера к Б.
  - [по STATE] Решение Б-1 риск смягчило, но не закрыло: `create-agency --username` не проверяет глобальную уникальность.
- **Разделение агентств** [ФАКТ: `trpc.ts`]: `agencyId` и id брокера берутся только из `ctx.agent`. [по ревью] Подбор по SQL фильтруется по `agencyId`. На чужую запись возвращается `NOT_FOUND`.
- **Обход входа для разработки** [ФАКТ: `env.ts`]: с `AUTH_DEV_BYPASS=1` в production сервер не стартует; в compose принудительно `"0"`.
- **Секреты:**
  - в дереве `.env` нет, `.gitignore` закрывает `.env*`, кроме `.env.example`;
  - [ФАКТ: `.env.example`] все секретные поля пустые, заполнены только несекретные значения: имя бота, адрес Yandex API, имя модели;
  - CI использует явно фиктивные значения;
  - история на ключи: по ревью этапов 1–3 чисто, `git log -p` CTO не запускал.
- **Порты** [ФАКТ: `docker-compose.yml`]:
  - наружу открыт только Caddy: 80, 443, 443/udp;
  - у `app` только `expose`, `db` в сети `internal: true` без публикации;
  - вебхук `/api/tg-webhook` Caddy принимает только с IP из `WEBHOOK_ALLOWED_IPS`; с пустым значением compose не запускается;
  - CSP ставит приложение (middleware).
- **Открытые замечания:**

**11. Риски (выводы).**

Технические:
1. **Выкладка не проверена.** Сервер не выбран, маршрут бота через Амстердам не настроен, бэкап на живом сервере не прогнан. Срок и риск пилота зависят от этапа 8 и действий собственника.
2. **Контакты клиентов могут утечь** через заметки, теги и «Быстрое добавление».
   - Вырезание улучшили, но оно работает на регулярных выражениях: имена людей не ищутся, полноту никто не гарантирует.
   - Поэтому правило «телефонов клиентов в базе нет» держится на коде и дисциплине брокеров.
3. **Движок и очередь работают на одной БД и в одном процессе.** Узкие места: транзакция пересчёта 120 с, общая очередь фото, нет лимита памяти. Для 50 брокеров это терпимо, для выхода на рынок — нет.

Бизнес:
1. **Модели монетизации нет** ни в коде, ни в ТЗ: к рынку продукт идёт без цены.
2. **Зависимость от одного агентства и от выгрузки baza.ayax.ru.** Если данных будет мало или они окажутся плохими, пилот ничего не докажет.
3. **Правовая база не закрыта:** оператор ПДн, трансграничная передача для Claude, условия использования выгрузки. Решения собственника по этим пунктам нужны до загрузки реальных данных.
